01 // Bối cảnh

Khi pipeline lỗi, dữ liệu bị chia nhỏ ở nhiều nơi

PROBLEM
LOG

Log phân tán

CI/CD, ứng dụng, quality report và hạ tầng dùng các nguồn quan sát khác nhau.

CTX

Thiếu ngữ cảnh

Kỹ sư phải tự nối run, commit, failed stage, diff và phiên bản triển khai.

RCA

RCA thủ công

Đọc hàng trăm dòng log và tra cứu runbook phụ thuộc kinh nghiệm cá nhân.

RISK

Recovery rủi ro

Retry hoặc rollback thiếu policy, approval và verification có thể gây sự cố mới.

Mục tiêu không chỉ là “đọc log bằng AI”, mà là xây một quy trình incident có bằng chứng và ranh giới an toàn.
Nhấn mạnh bài toán hệ thống chứ không chỉ là bài toán mô hình. AI chỉ có ý nghĩa khi dữ liệu đầu vào được correlation và đầu ra đi qua kiểm soát an toàn.

02 // Mục tiêu

Một control plane đứng ngoài CI/CD

SCOPE
  • Chuẩn hóa telemetry từ nhiều provider.
  • Incident tự động khi quality gate hoặc pipeline thất bại.
  • Evidence có provenance, checksum và redaction.
  • Hybrid RAG tìm runbook và incident tương tự.
  • Recovery có kiểm soát bởi policy, approval và verification.

Ranh giới MVP

GitHub Actions là provider đầu tiên

Pipeline batch · self-hosted · không thay thế CI/CD · không tự merge code · không cho LLM trực tiếp thao tác production.

Provider-neutral core
Giải thích control plane là lớp quản lý, không thay thế GitHub Actions. GitHub được dùng để làm MVP, nhưng domain model và recovery contract không phụ thuộc GitHub.

03 // Runtime flow

Từ một lần push đến kết quả có thể kiểm toán

END-TO-END
01 · Pushcommit + branch + run ID
→
02 · ExecuteAgent chạy stage tuần tự
→
03 · Ingestevent + log + report
→
04 · Correlaterun state + idempotency
SUCCESS PATH

Không gọi LLM

Hoàn tất run, hiển thị dashboard và verification. Overhead chủ yếu là callback và upload report.

FAILURE PATH

Tạo incident

Evidence → Hybrid RAG → RCA → Policy → Approval → Recovery → Verification.

Agent giữ nguyên exit code của stage; Platform tạm unavailable không được làm đổi kết quả kiểm thử gốc.

Điểm quan trọng là happy path không gọi AI. Failure path chạy bất đồng bộ về mặt quy trình; CI không phải chờ con người đọc RCA để hoàn thành kết quả gốc.

13 // Function calling

“Có capability tools” chưa đủ để giao quyền thực thi

FUNCTIONGEMMA TEST
✓

Điểm đạt

Nhận biết được tool lấy pipeline status trong prompt kiểm thử.

×2

Duplicate call

Gọi cùng tool nhiều lần, kể cả trong kịch bản chỉ có một tool.

TYP

Sai argument

Giá trị numeric được sinh thành string và thêm tool không liên quan.

Output không sạch

Sinh thêm nội dung rác, không dừng đúng sau function call và chạm giới hạn độ dài.

Kết luận

FunctionGemma chưa được tích hợp; mọi tool call có side effect phải validate và idempotent.

Tool calling là dữ liệu đầu vào cho Policy Engine — không phải đường tắt đi thẳng tới production.
FunctionGemma khoảng 268 triệu tham số, Q8_0. Test không thực thi tool thật. Kết quả cho thấy cần lớp schema validation, allowlist và idempotency phía server.
